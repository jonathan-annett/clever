# clever

Browser-based real-time audio analyzer for live sound, in the spirit of Smaart Live. Part of audiogeek. Live at https://audiogeek.sophtwhere.com/clever/

The owner is a live sound engineer. He tests on real gear at venues, so anything that touches measurement accuracy needs care.

## Files

| File | Purpose |
|---|---|
| `index.html` | The whole app: HTML, CSS and two inline scripts. No build step, no dependencies. |
| `guide.html` | User guide for people new to measurement. Linked from the ? button and the About section. Keep it in step with UI labels when they change. |
| `guide.m4a` | Audio overview of the guide (NotebookLM). Lives only on the server; listed in `.gitignore` because it is too big for the repo. The guide links to it, and the service worker skips media requests. |
| `redirects/` | Stubs and instructions for sending the old audiogeek pages (`/` and `/levels.html` on the site root) to clever's Bands and Levels tabs. Not used by clever itself. |
| `sw.js` | Service worker. Network first with a 4 s timeout, cache fallback for offline use at venues. |
| `manifest.webmanifest` | Home-screen install (name "clever by audiogeek", short name "clever"). `display` is `fullscreen` (with `standalone` as fallback) so the installed Android app hides the system bars. |
| `icon-*.png` | App icons (192, 512, maskable 512). |

Keep it a single self-contained page. Don't add a bundler, framework or npm dependencies unless the owner asks. One agreed exception: the optional Voice transcript loads transformers.js 3.8.1 from jsDelivr in a worker, only when the user presses its button after a download warning.

## Deployment

- Served by the owner's Node/Express server as static files under `/clever/`, over HTTPS. Mic access and WebHID require HTTPS.
- The server folder is a git clone of this repo. The owner deploys by running `git pull` on the server, usually over SSH from Termux on his phone. There is no CI.
- All paths are relative (manifest `start_url` and `scope` are `./`, the service worker is registered as `sw.js`). Keep them relative so the app works in any subfolder.
- When you change cached assets, bump the version in `CACHE` in `sw.js` (currently `clever-v38` on alpha, `clever-v37` on main, followed by the folder path) so installed copies refresh.
- **Branches:** `main` is the live site (`/clever/`). New work goes to the `alpha` branch, which the owner runs as a git worktree in a `clever-alpha` folder next to the live one (`/clever-alpha/`). Commit and push to `alpha` and tell the owner to pull in `clever-alpha`. Only when the owner says a feature is ready, merge `alpha` into `main`, push, and tell him to pull the live folder. Urgent fixes to the live site go on `main` and are then merged into `alpha`. The live commit when this started is `e54dc49`.
- **Copies side by side:** a copy in a folder named `clever-<name>` keeps its storage under `ca.<name>.*` (`CHAN`, `skey()` in the settings section), copied once from the live keys the first time it opens, and shows its name next to the logo and in the title. Each copy's service worker names its cache after its folder (`SCOPE`) and only deletes its own old versions; the live copy also clears the old unnamed caches.

## Code map (`index.html`)

1. `<style>`: dark-only design on purpose (used in dark venues). Tokens on `:root`. `[hidden]{display:none!important}` must stay, or elements with their own `display` ignore the hidden attribute. Under 900 px the settings panel becomes a slide-out drawer; above that, `.app.nside` collapses it (`P.sideHidden`, key S). The ☰ button handles both.
2. `<script id="dsp">`: pure DSP with no DOM access, also exported for Node (`module.exports = DSP`) so it can be unit tested. Contains a radix-2 FFT, Hann window cache, prefix sums with fractional-bin integration (`cum`), GCC-PHAT delay finder, A and C weighting, log-frequency interpolation and the cal file parser.
3. Main script, in banner-commented sections:
   - **settings**: `P` is the persisted settings object (`DEFAULTS` merged with `localStorage`). Call `changed()` or `save()` + `syncUI()` after mutating it.
   - **audio worklets**: the `WORKLET` string is loaded as a Blob URL. `ca-cap` captures input 0 (reference) and input 1 (measurement) in 1024-sample blocks. `ca-gen` produces pink (Paul Kellet filter, normalised to RMS 1), white or sine at an RMS dBFS level.
   - **engine**: `start()` builds the AudioContext graph. Echo cancellation, noise suppression and auto gain are switched off. The reference is either the generator (internal loopback), a device channel, or (`P.refCh === 'sum'`, only when the reference has its own device) an L+R mono sum through a 1-channel GainNode. Pass-through (`P.thru`, `P.thruLevel`, `S.thruG`, `thruApply()`): the reference input is played to `ctx.destination` (the Output device) so a music source can feed an amp directly; the whole stereo stream when the reference has its own device, only the reference channel when it shares the mic's interface. The generator is muted while pass-through is active (`sendGen`, `toggleGen`). No special latency handling is needed: GCC-PHAT compares the captured reference with the mic, so the browser's output latency is part of the measured delay (tested with a simulated 8.5 ms path, found exactly). A screen wake lock is held while running.
   - **analysis**: ring buffers of 2^18 samples. Multi-time-window FFT sizes are 16k down to 512 at 48 kHz (doubled at 88.2 kHz and above). The `MTW_BOUNDS` crossovers are 200, 400, 800, 1600 and 3200 Hz. Cross-spectra are averaged per size. A residual sub-sample delay is applied as a phase rotation. Smoothing is complex smoothing over fractional-octave bands via prefix sums. The display grid is 1/48 octave, 18 Hz to 22 kHz.
   - **delay finder**: GCC-PHAT over 65536 samples with parabolic interpolation. A confidence ratio below 8 is rejected. Negative delays delay the measurement instead of the reference.
   - **SPL**: 4096-sample non-overlapping blocks, frequency-domain weighting including mic cal correction, Fast and Slow exponential time weighting, Leq and Max.
   - **levels**: two engines, `LEVS.meas` and `LEVS.ref`, both always running (`levFeed()` per input from `onAudio`; the reference's weighted level comes from `refWBlock()`, without mic calibration or SPL offset). `LEV` points at the one selected by `P.levSrc` (set in `syncUI`). References are keyed `metric` for the mic and `ref:metric` for the reference input (`levRefKey`). Each engine is a ring buffer of 100 ms points (11 min) filled from `onAudio`, so it keeps recording while other tabs show. Per sample: BS.1770 K-weighting (`DSP.kWeight`, verified: 1 kHz 0 dBFS sine = −3.00 LUFS). Per 100 ms block: K-weighted, unweighted and SPL-weighted mean squares (the weighted one comes from `splBlock`), each averaged over a 3 s window and stored as LUFS, dBFS and weighted dBFS (SPL offset added at display time), plus 400 ms momentary versions (`km`, `rm`, `wm`). The view defaults to 60 s (`P.levSpan` 1, 3 or 10 min; wheel, − and =, header button). At 60 s it draws the old levels page's boxes: last 5 s (red) and 60 s (green) from momentary mean to momentary peak. `P.levRefWin` is an average window in seconds or `p5`/`p60` for a peak. The readout shows the 3 s drift and a steadier 60 s average drift. `P.levRef` holds one reference per method; the drift readout is current minus reference. Click or drag on the graph sets the reference (`S.levDrag` freezes the y-range while dragging).
   - **bands**: built for ringing out with an analog graphic EQ: the band matters more than the exact frequency. `BAND_PRESETS` (iso31 default, iso33, dn30, oct23 15-band, oct1 10-band, custom from `P.bandCustom`, parsed by `parseBandList` which accepts `2k5`/`2.5k`). `bandSet()` derives edges at geometric midpoints between centres. `BANDS.rows` keeps 1500 rows of band levels from the response-averaged spectrum, each with `v` (mic, calibrated) and `vr` (reference input, from the new `rtaX`/`cRtaX` accumulators); `P.bandsSrc` picks which one is shown (`bandsKey()`). Rows also carry `va`, the solo channel (from `S.auxSpec`, the per-tick `auxSpectrum()` shared with Voice, band powers smoothed with the RTA response time in `BANDS.auxE`; NaN while the solo channel isn't connected); the source button offers Solo while it's connected or has history. Rows hold unweighted levels; `P.bandsWeight` (Z/A/C) is applied at draw time by `bandsVals(row)` using `bandsWeights()` (each band's power-averaged weighting, flat spectrum assumed; A gives −39.3 dB at 31.5 Hz, 0 at 1 kHz) and cached on the row, so the whole history switches on toggle. A fourth weighting, N (experimental), uses `P.bandNoise` (`{key, t, v, vr, va}`: per-band mean level over the last 2 s for each input, saved by `bandsSetGateFromNoise()` for the current layout key): each band gets `mean noise − its noise`, so the noise floor draws flat and its power total is unchanged (white noise: 30.7 dB band spread became 2.7 dB, total equal). Without a matching profile N falls back to unweighted and the header says to press Set from noise (`bandsWeightOn()`). Solo checked with an injected 1 kHz sine at −20 dBFS: 1k band read −20.00. Rows are pushed each analysis tick and cleared when the layout changes. `drawBands()` redraws from history every frame: waterfall, hot zone (loudest non-ignored band) in red, a hot tally strip (share of the last `P.bandTallySec` s each band was loudest) and a big readout of the tally leader (red at 60 % or more). A silence gate (`P.bandGate`, dBFS, default −60) compares each row's overall level (`bandsTotal`, ignored bands excluded) and treats quiet rows as having no hot band, so they don't count, aren't marked red and hide the readout; `bandsSetGateFromNoise()` sets it 6 dB above the last 2 s. Ignored bands are stored by frequency in `P.bandIgnoreHz`, migrated once from the old 33-flag `P.bandIgnore` or the old analyzer's `ignoreBars` key.
   - **solo / second reference channel**: `P.refAux` (only when the reference has its own 2-channel device and `refCh` isn't `sum`) connects the reference device's other channel to the capture worklet's third input (`ring.aux`, `S.auxOn`, `S.auxCh`, SOLO meter). Pass-through then plays only the reference channel. Voice can use it as source `aux` (`auxSpectrum()`: one Hann-windowed 16k FFT per tick, independent of the MTW accumulators). Note: Chrome's fake test device is stereo with an intermittent full-scale beep on channel 2, so tests must not leave that channel connected to the third input.
   - **voice**: a vocal check. `pushVoice()` builds a speech-gated long-term average spectrum in 1/24-octave bands (`VOICE_FC`, 50 Hz–16 kHz) for both inputs from the instantaneous spectra (`inst`/`cInst` for the mic with calibration, the new `instX`/`cInstX` for the reference). Frames only count when the 100 Hz–5 kHz level is above `P.voiceGate`; averaging is exponential over `P.voiceTau` seconds of speech, or cumulative until New talker. `DSP.voiceAnalyze(fc, L, { hpfOrder, cfg })` (pure, Node-testable) compares the 1/3-octave curve with an approximate LTASS shape (Byrne 1994) normalised over 300 Hz–2 kHz and returns the zone energy split (below 100 Hz / 100 Hz–5 kHz / above 5 kHz), findings and suggested cuts: high-pass (sub excess over 6 dB), low-mid bell (150–450 Hz excess over 3 dB), resonance notches (1/24-octave peak at least 4 dB above its flanks, 8 dB below 400 Hz, Q from the −3 dB width), nasal, harsh and sibilance bells, plus advice-only findings for HF dominance, thin and dull. Cuts only; the cost of each cut is the drop in band-importance-weighted speech level (approximate ANSI S3.5 weights). Synthetic tests: no findings on 200 natural voices with ±1.5 dB ripple; proximity, a 2.5 kHz Q8 resonance, a 1.2 kHz Q5 resonance, hiss and a distant talker were all caught. `voicePanel()` renders the suggestions as HTML over the plot. Every range, trigger, maximum cut and Q (and the zone edges, resonance settings and cost warning) lives in `DSP.VOICE_DEFAULTS`; the user's overrides are `P.voiceCfg` (only the changed keys), merged by `DSP.voiceCfg()`. `sens` multiplies every trigger (Gentle 1.5, Strict 0.75) and `depth` scales every cut. The settings UI (Sensitivity, Cut depth and the Rules panel built by `voiceRulesBuild()` from `VOICE_RULES`/`VOICE_GLOBALS`) writes through `voiceCfgSet()`. The numbers quoted above are the defaults. The panel doesn't show raw findings: `voiceTrack()` turns them into entries in `VH.entries` keyed by rule (`voiceKeyOf()`; resonances also by 1/3-octave band), shown after `VH_SHOW` (2 s) of steady presence, kept in first-shown order and listed until `VH_DWELL` (10 s) after last seen, then moved to Earlier. `VH.paused` freezes the view (snapshot of each entry's finding) while tracking continues; `voiceNewCount()` counts what arrived since. Momentary events come from `DSP.voiceEvents(fs)` (pure, Node-tested): per 20 ms frame, levels below 60 Hz (4th-order low-pass), 300 Hz–3 kHz and 5–11 kHz, against a running speech level (after 1 s of speech): a pop is a low burst within `ev.popThr` (−6) dB of speech that is 3 dB above the core band in its own frame and 14 dB above the last half second (no events in 5 × 30 s of pink noise); sibilance is 5–11 kHz within `ev.sibThr` (−3) dB. Events are reported at onset and extended while they last. Synthetic checks: no events on male 90/110 Hz or female 210 Hz speech or a natural S at −12 dB; S flagged from −6 dB, pops from −3 dB. `voiceEventsFeed()` runs it from `onAudio` on the Voice source; `voiceEventAdd()`/`voiceSibFix()` attach the fix. `voicePanel()` renders Now, the Moments strip (`VH_SPAN` 60 s) and Earlier; taps use pointerdown because the panel is redrawn every 500 ms. `S.voiceShown` holds the numbered findings for the deck's cut keys. Channel strip: `DSP.stripFit(fc, L, D, {strip, depth, sib, prev})` (pure, Node-tested) builds a cut target per 1/24-octave band from the broad deviation (D re-centred on its 30th percentile over 200 Hz–6 kHz, minus 1 dB) combined with narrow peaks (level over flanks, kept whole once a peak clears 2.5 dB, 6 dB below 400 Hz) and recurring sibilance from the events; weights are SII importance times (1 + (excess/4)²), overcutting is penalised 3×, and bands below the low cut (×1.25) or above the high cut are ignored. It picks bands greedily (bells at 11 Q values within the configured range, low shelf in slot 1 and high shelf in the last slot when allowed; a band must reduce the cost by 3 % of the start), refines f, Q and gain by coordinate descent, keeps the previous answer unless a fresh one is 15 % better, rounds to console values and assigns slots. `filterDb` also does RBJ shelves (S = 1, f = midpoint). Synthetic checks: proximity, resonance, bright mic and five overlapping problems fitted (93 % covered, shape error 1.6 → 0.8 dB), 3-band and bell-only desks respected, no bands on 50 natural voices, no changes over 20 warm-started refits; 40–100 ms per fit. `stripUpdate()` runs it every 2 s from `voiceCompute`; `P.strip` holds only non-default settings (`stripCfg()`); deck keys `eq1`–`eq4` are on the Voice page; the plot's numbered markers and dashed line are the strip. Transcript (experimental, owner-approved download behind a confirm): `TR_WORKER_SRC` is a module worker (Blob URL) importing `TR_LIB` (transformers.js 3.8.1 on jsDelivr) and running `pipeline('automatic-speech-recognition', TR_MODELS[P.trModel])` with `return_timestamps: 'word'`; models are `onnx-community/whisper-tiny.en_timestamped` / `whisper-base.en_timestamped` (they carry `alignment_heads`), dtype encoder fp32 + decoder_model_merged q4 on WebGPU, q8 decoder on WASM. `trFeed()` (from `voiceEventsFeed`) low-passes at 7 kHz and resamples the Voice input to 16 kHz, cutting chunks at a 300 ms pause after 4 s or at 12 s, skipping chunks with under 0.6 s above the speech gate; the queue holds 2 chunks and drops the oldest with a '…' gap marker. Words (`TR.words`, memory only, cleared by New talker) are placed on the same `performance.now()` clock as the events and highlighted when an event overlaps within 80 ms; tapping one selects the event. `P.trOn`, `P.trModel`, `P.trReady` (model already downloaded, so a reload restarts it without asking). sw.js caches the versioned library cache-first in `clever-lib` and only deletes old `clever-v*` caches, because the model files live in transformers.js's own `transformers-cache`. Tested with a mock worker only; the real model could not be downloaded in the sandbox.
   - **test speaker**: correction for a (cheap, often Bluetooth) speaker used as a test source. `spkStart('measure'|'check')` needs the analyzer running, Reference = generator and no pass-through; `spkTick()` (from the analysis tick) listens 0.8–2.8 s with the generator off (room noise), turns pink on, waits 1.5 s, then averages 12 s of `spkBands()` (1/12-octave band powers of the mic, calibrated, and the generator from `cInst`/`cInstX`). `spkFinish()` stores `P.spk = { t, H, valid, cal, check }` (H = mic − generator per band, valid where 10 dB above noise). `DSP.spkFit()` (pure, Node-tested) smooths (1/`P.spkSmooth` oct), normalises to the 300 Hz–3 kHz median, corrects within the range where the speaker is within `P.spkLift` dB (usable range), rolls off at 24 dB/oct outside it and normalises so the filter only cuts (`drop` = how much quieter). `DSP.firFromDb()` makes a linear-phase FIR (8192 taps, 16384 at 88.2 kHz and up) for `S.spkConv`. Engine: gen → `S.genDirect` → output and gen → `S.spkConv` → `S.spkGain` → output, switched by `spkApply()`; the reference always gets the plain generator, so a transfer function against it measures the mic under test. Synthetic speaker (HPF 130 Hz, +6/−5/+4 dB bumps): −10/+5 dB became about ±1.5 dB, FIR within 1 dB of the design. Untested with a real speaker. Deck action `spkEq` (not on a default page). The generator chip shows EQ when it's active.

Target curves: `TARGET_PRESETS` (by mic type, plus two PA curves) and the user's `P.targets` (`{id, name, pts: [[Hz, dB]…]}`), `DSP.targetAt()` interpolates on log frequency; the builder (`tgBuild()`) edits points, and editing a preset makes a copy. Synthetic gooseneck (+5 dB at 220 Hz, +6 dB Q6 at 3.2 kHz, a −4 dB notch at 1.3 kHz): −4 dB at 230 Hz and −6 dB Q8 at 3.2 kHz, notch left alone, 97 % covered.

## Measurement conventions

- **dBFS** is sine-referenced: a full-scale sine reads 0 dBFS. RTA band level is `10·log10(4·Σ|X|² / (N·Σw²))`.
- **Transfer function**: `H = Gxy / Gxx` with ref = X and meas = Y. Coherence is `|Gxy|² / (Gxx·Gyy)` per bin, then averaged across each smoothing band.
- **Mic cal files**: text files of frequency/dB pairs. The values are the mic's deviation, so they are subtracted. A UMIK-1 header line looks like `"Sens Factor =-1.378dB, AGain =18dB, SERNO: 7001234"`.
- **SPL offset default**: `112 − SensFactor`, from the UMIK-1 nominal −18 dBFS at 94 dB SPL. This is approximate and the UI says so. The Dayton iMM-6C file has no sensitivity, so it needs the calibrator button. Offsets are saved per mic profile.
- **UMIK-1 cal URL**: `https://www.minidsp.com/scripts/umikcal/umik90.php/<7-digit serial>[_90deg].txt` for both 0° and 90° (confirmed by the owner from real downloads; the old `/images/umik/` path no longer works). miniDSP sends no CORS headers, so the app falls back to showing the link for manual download. The owner prefers that manual flow because he gets the .txt file on disk too. Don't add a server proxy unless asked.
- **Dayton iMM-6C**: no direct URL. The user looks the file up by serial at https://support.daytonaudio.com/MicrophoneCalibrationTool.

## Stream Deck (WebHID)

Vendor ID 0x0fd9. Supported product IDs: XL 0x006c and 0x008f (8×4, 96 px keys), MK.2 0x0080 and 0x00a5, V2 0x006d (5×3, 72 px). These are the gen-2 protocol:

- **Key images**: JPEG, rotated 180°. Sent as output report 0x02 in 1023-byte data packets: header `[0x07, key, isLast, lenLo, lenHi, pageLo, pageHi]` then up to 1016 bytes of payload.
- **Brightness**: feature report 0x03 with `[0x08, percent]`, padded to 31 bytes. Reset is `[0x02]`.
- **Key presses**: input report 0x01, key states start at data offset 3.

The protocol was written from community documentation and has been confirmed working on the owner's Stream Deck XL. If another model misbehaves, suspect the key index mapping and the input report offset first. Android Chrome has no WebHID, so the app hides the connect button there and offers only the on-screen console.

## Testing

- Playwright with Chromium is available in the cloud agent sandbox (`/opt/npm-tools/node_modules/playwright`, browsers in `/opt/pw-browsers`). Serve the folder with a tiny static server, launch with `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` for a fake mic, and screenshot. To judge transfer function drawing, set `S.tf` to synthetic `{f, mag, ph, coh}` arrays, because the fake mic doesn't correlate with the generator. Google Fonts are blocked there, so text falls back to system fonts.
- No test suite. To check the main script's syntax, extract it and run `node --check`.
- To test the DSP, extract the `#dsp` script and `require()` it in Node. Earlier simulated checks passed: GCC-PHAT recovered a 1234.4-sample delay, the transfer function read −6.02 dB for a 0.5× gain with the expected residual phase, and a full-scale sine read 0.00 dBFS.
- Visual or UI changes still need the owner to look on his devices.

## Planned: phone as a remote

For people without a Stream Deck: a phone shows the on-screen console and controls clever on a laptop. Not started; the owner wants to use clever more first and move the domain to its own VPS before adding WebSocket traffic. Agreed design:

- **Transport:** a small WebSocket relay on the owner's server (the `ws` package, a module in this repo plus a two-line hookup in his Express app). Both clever and the phone connect outward, so it works on venue Wi-Fi, mobile data or a phone hotspot. No WebRTC: it still needs signalling through a server, and Chrome's mDNS host candidates and carrier NAT make direct links unreliable on hotspots, for little gain on button presses. WebRTC could be layered on later with the relay as fallback.
- **Pairing:** clever shows a QR code with a random room code; scanning it opens clever in remote mode (console only, full screen). clever shows a notice when a remote connects and can disconnect all remotes.
- **Messages:** key presses from the phone; key faces (the `ACTIONS[i].k()` objects, only those whose signature changed) from clever, so the phone draws them with `drawKey()`. Tap versus hold is decided on the phone, which sends `press` or `hold`, so network jitter can't turn a tap into a hold.
- **Shared relay:** the same relay may serve other integrations later; plan it with the owner rather than building something specific to the remote.
- **Before building:** ask whether anything sits in front of Express (nginx, Caddy, Cloudflare) that needs WebSocket upgrades enabled, and whether the remote should also show SPL and Levels readouts.
